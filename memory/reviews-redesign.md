# 已驗證評論系統重構

**日期**：2026-07-21（2026-07-22 正式入口切換）

## 目的

舊版評論把評分鎖死、以 thread 和圖片堆疊互動，官方訊息與一般訊息的責任邊界也不清楚。新版以「可驗證、可修正、不可代改、可治理」為核心，讓公開評價更可信，同時避免公開帳號姓名或 Email。

## 長期決策

- 發表資格以至少一筆完成的 `ScanJob` 驗證；staff 不得作為一般使用者發表。
- 一人一則 `PlatformReview` 不變，但本人可修改 rating/title/comment/display_name 或刪除；修改前版本存 `ReviewRevision`。
- 公開作者名稱只用評論者自行填寫的 `display_name`，留白顯示「匿名已驗證使用者」；禁止由 User 姓名或 Email 推導。
- 公開列表與統計只納入 `published` 且 `experience_at` 有值的評論。
- 官方回覆改為每則最多一筆 `ReviewResponse`，管理員可新增、更新或刪除，但不能覆寫使用者評分與原文。
- `ReviewReport` 負責檢舉；管理員以 published/hidden 治理，並將待處理檢舉結案或駁回，操作寫 `review_moderate` audit。
- `ReviewMessage` / `ReviewMessageHelpful` 只保留舊資料與 migration 相容，不再暴露公開端點；migration 會把舊版最後一則管理員訊息搬到 `ReviewResponse`。
- 公開頁獨立放在 `frontend/src/features/reviews/ReviewsPage.jsx` 並由路由 lazy load，避免再把評論流程塞回帳戶頁集合。
- 夜間科技版已正式接管 `/reviews` 與 `ReviewsPage.jsx`；舊版元件及專用 CSS 移除，`/reviews-next` 只保留到 `/reviews` 的相容轉址，不再維護第二套頁面。
- `/reviews` 必須掛在共用 `PublicLayout` 內，沿用全站唯一的 `PublicNav` 與 `PublicFooter`；評論元件本身不得再建立頁面級 header 或 footer。
- 正式版將官方回覆標示為「Argus 官方回覆」；這是公開品牌身分，不是登入帳號名稱。品牌小圖以既有 `brand-logo.webp` 裁切顯示，只保留眼睛圖形且不加正方形外框。
- `BrandEye` 的小尺寸裁切框固定為 42×27px、圖片固定為 60px，桌面與手機皆維持 0.7 的水平可視比例；外層回覆排版不得覆寫元件尺寸。
- 正式版採單欄社群討論流；helpful 只顯示按讚圖示與數字，排序文字使用「熱門／最新」。
- 使用者評論與 `ReviewResponse` 都是可被單獨評價的內容：各自擁有按讚數、本人按讚狀態與檢舉目標，操作緊貼該段內容，不設整串對話共用的操作列。
- 逐則互動列維持社群常見的按讚在左、檢舉在右，中間保留完整安全距離，避免兩個圖示相鄰造成誤觸。
- 官方回覆整個色塊不跟隨使用者正文縮排，左緣與評論卡的內容邊界對齊；回覆互動列的讚跟隨官方正文欄，桌面版正文／讚與使用者內容共用左基準線，檢舉共用右基準線，不得跨到品牌圖示下方。
- 評論檢舉與官方回覆檢舉在資料與後台統計上分開；父評論的隱藏／公開治理不得連帶結案官方回覆檢舉。
- 寫評論入口必須直接可見；本人已有評論時，以獨立「我的評論」區塊顯示編輯／刪除，並從一般公開列表排除，避免同一內容出現兩次。
- 評論頁只保留完成任務需要的文字，不顯示功能教學、滿分說明或版本跳轉文案；尚未具備發表資格的已登入使用者，留言入口改顯示「評論前先完成一次掃描」並直接前往掃描頁。
- `/reviews` 採單一評論正文，不顯示或編輯標題；正文與官方回覆超過四行時才顯示「顯示更多／收合」，短文不增加額外控制項。
- `/reviews` 目前只維護已確認的夜間版；日間版待夜間版定稿後再處理，不同時擴張兩套視覺。
- 夜間版使用深海軍藍表面層級、低飽和青色訊號光與琥珀星等；評論與回覆之間以縮排、色面和短垂直光軌建立關係，不在內容與互動間加入水平分隔線。
- 整體評分的數值與星等在評分欄內置中；版面堆疊時，評分卡限制最大寬度並相對 hero 水平置中。
- 正式版的逐則互動目標至少 48px；星等分布整列可點擊、檢舉使用紅色風險語意。動態包含背景網格／光暈、標題與評分進場、卡片錯峰、回覆展開與按讚回饋，只使用 transform／opacity／背景位移並支援 reduced motion。

## 驗證基準

- 後端：全 `apps` 測試、ruff、Django system check、migration drift check。
- 前端：使用 `frontend/build-node22.ps1` production build。
- 瀏覽器：桌機與 320px、深淺色、分布篩選/排序、撰寫表單語意、公開卡片、官方回覆、管理後台唯讀評分與治理控制；console 必須無錯誤。
- 正式夜間版：`/reviews` 必須涵蓋 2560px、1920px、1440px、1280px、768px、390px 與 320px，並同時檢查 0 則與有評論狀態；不得有標題／評分卡重疊或水平溢位。單行標題、逐則按讚／檢舉、篩選／排序、寫評論／掃描資格入口、本人評論分區與品牌圖裁切都需正確；`/reviews-next` 必須轉址到 `/reviews`。
