# 2026-08 日間主題光學反相重設計

## 使用者目標

改善公開網站日間模式過度淡藍、層次不足，以及品牌 Logo 在淺色背景被過度濾鏡與外框醜化的問題；同時讓日間與夜間模式有明確差異，但保留同一套 Argus 科技品牌語言。

## 設計決策

- 日／夜共用相同角色：背景、surface、文字、邊線、品牌 cyan、互動 blue；只替換明暗值與光線表現，避免維護兩套不對稱元件。
- 夜間以深空底、外發光與高亮邊線分層；日間採珍珠霧白底、冰藍玻璃、內光邊、柔和陰影與藍圖網格，形成「光學反相」。
- 日間保留首頁 grid、scanline、HUD corner 與 ambient orb，但降低不透明度，避免把科技感全部關掉後變成普通白色網站。
- 原始 `brand-logo.webp` 不重製；移除日間額外底框與過強的飽和／對比濾鏡，只做溫和降亮度與加對比，兼顧透明素材中的白色 ARGUS 字標。
- 主題切換圖示改為 inline SVG，避免 Unicode 太陽／月亮因作業系統字型而呈現不同；按鈕仍保留文字標籤與動態 `aria-label`。
- 公開導覽在 1180px 以下隱藏副標，920px 以下切為品牌／CTA 上列、導覽連結下列；390px 仍維持無水平溢出與足夠點按範圍。
- 日間卡片以白／冰藍交替 surface、低彩度藍邊與內光建立層級；團隊卡的飾條與 avatar ring 收斂為 cyan → blue → indigo，不另引入新品牌色。
- 比較型表格以功能敘述本身作為每列識別，不另加「檢測／AI／報告／計價／體驗」分類膠囊；正文固定高對比中性色，Argus 使用唯一品牌藍，自己做與競品只靠兩階冷灰 surface 區隔。日／夜替換明度與材質，但維持相同層級。
- 公開頁若另有頁面級主題 class，必須由全域 Zustand `theme` 決定，不可把夜間 class 寫死；`/reviews` 以 `review-next-day`／`review-next-night` 切換整頁角色色，評分、評論卡、官方回覆與隱私控制同步換色。

## 驗證基準

- `frontend/build-node22.ps1` production build 必須通過。
- 以瀏覽器巡覽 `/project`、`/team`、`/free-tools`、`/purchase`、`/download`、`/reviews`，確認日間模式、主題切換、Logo、卡片與 console。
- 視窗寬度至少檢查 1280、936、900、390；不得有水平溢出，936px 不得再出現品牌副標逐字直排。
- 主要文字、次要文字、品牌強調與 CTA 端點以 WCAG 對比公式核對；一般文字至少 4.5:1。
