# 專題手冊維護規則

程式碼是系統事實的最終來源。接手與修訂以 [交接檔案](交接檔案.md) 及 [v10 編製契約](編製紀錄/v10/artifact.md) 為入口；原本的需求書資料夾沒有被現行編製程式讀取，已退出目前流程並留作本機歷史封存。

## 變更時同步哪些資料

對外可見功能、API、model、計費邏輯與前端操作流程變更時，必須同步手冊來源、版本交接及驗證紀錄。先讀程式碼與實跑結果，不得直接把舊手冊內容當成現況。

v10 使用 `本機資料/` 中的 v4 原稿、v9 技術原稿，以及 `work/v10/` 編製資料。工具位於 [編製紀錄](編製紀錄/README.md)，以相對位置讀取原始工作區；舊複賽需求書 Markdown 不是其輸入。缺少本機原稿時，不得宣稱可只靠 Git 重建完整手冊。

## 修訂與驗收流程

1. 閱讀 v10 契約、現況、QA 與 [歷史測試結果](編製紀錄/歷史測試摘要.json)，先備份原稿；保留未通過與未驗證項目。
2. 依此次改稿範圍更新真正的來源。若修訂 v9 技術內容再匯入 v10，使用 `本機資料/work/v9/` 的章節資料與原稿流程；不得再要求更新已退出流程的舊需求書。
3. 核對 v10 的來源匯入範圍。其構建腳本使用 v9 XML 區塊索引，新增或刪除來源段落後須確認索引與保留內容仍正確。
4. 依目前可用的文件工具重新編製、匯出與渲染。主代理及獨立視覺 QA 實際觀看受影響頁面；分頁變動時核對全部目錄與書籤。語法、XML 或 OCR 不能代替版面驗收。
5. 更新 [交接檔案](交接檔案.md)、版本契約、QA、稽核結果與分享來源清單，執行 [MD 核對清單](../docs/md-checklist.md)。未重新執行的檢查明確標為歷史結果。

原始 Word、設定、私人截圖及完整 PDF／PNG 留在 Git 排除的 `本機資料/`。分享紀錄保留狀態與數字，遮蔽私人資訊，不覆寫原稿。本次整理與移除舊資料夾不代表新功能已整合進 v10，也不代表重新完成版面驗收。
