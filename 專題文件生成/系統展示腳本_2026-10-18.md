# ARGUS AI 網站健檢平台 — 評審系統展示腳本

> 目標：在評審面前，用 **新用戶／會員 → 管理員（staff）→ 超級管理員（superuser）** 三種角色，走完所有
> 必要頁面與功能，並回扣初審三位委員的意見。全程「先授權、再掃描、證據為本」。
> 建議總時長 **12–15 分鐘**（問答另計）。操作者照「做 → 說」兩欄走；「說」是講給評審聽的重點。

---

## 事前準備（展示前 10 分鐘完成）

1. **三個帳號各開一個瀏覽器分頁／視窗**（避免現場切換帳號卡住）：
   - 會員：一般帳號（新帳號自帶「晨光咖啡烘焙所」示範專案）。
   - 管理員：staff 權限帳號。
   - 超級管理員：superuser 帳號。
2. **預先備好「已完成」的掃描**：現場即時掃要數分鐘，**不要賭現場掃完**。用示範專案既有的完成掃描，或
   事前對一個自備 3–5 頁小站掃好一次當 demo 實例（回扣委員 1 的「簡化實例＋修復清單」）。
3. **備援**：先把 1～2 份 PDF 報告下載到本機，萬一網路不穩可離線展示。
4. **部署確認**：若要展示「加做 AI Agent 深度資安測試」勾選、分數分離、OWASP 2025 顯示，先確認正式站
   已部署含最新 commit 的後端並重啟 worker、前端已 build。**未部署就口頭說明是最新版本，用報告佐證**。
5. 瀏覽器縮放調到評審看得清楚；開日間或夜間主題擇一固定（別現場切來切去）。

## 逐頁口頭說明稿（照念版，2026-10-20 補）

> 上面的表格是「做什麼、講重點」；這一節是每一頁可以直接照念的完整說明，每段 30～60 秒。
> 結構固定：先講這頁回答什麼問題，再指畫面上的東西，最後一句收在「這代表什麼」。數字以當天畫面為準。

### 會員區

**公開首頁 `/project`**
「Argus 是一個網站健檢平台。使用者只要給一個網址，我們用真實瀏覽器把網站爬一遍，從五個面向檢查：SEO 搜尋引擎找不找得到你、AEO 問答引擎答不答得出你、GEO 生成式 AI 願不願意引用你、UX 手機上好不好用，以及資訊安全。流程是『先授權、再掃描、證據為本』——每一個問題都能追到是哪一頁、哪個位置、怎麼修。」

**快速檢查 `/free-tools`**
「這是不用登入、不扣點的公開工具：單頁四維健檢、網站測速、釣魚網址與釣魚郵件判斷。目的是降低第一次接觸的門檻，先讓使用者看到 Argus 看得出什麼，再決定要不要註冊做完整掃描。」

**註冊／登入 `/login`**
「註冊一律先用 Google 驗證信箱，再設定用戶名與密碼，每個帳號背後都有一個真實 Google 帳號，大量開小號的門檻很高。登入與註冊都有 Cloudflare Turnstile 擋機器人。」

**所有專案 `/projects`**
「會員區以『網站專案』為單位，一個專案對應一個網站。這一頁一列一個網站：最新分數與上次比的變化、歷次走勢、五個維度各自的分數、目前問題依嚴重度的數量、上次掃描時間。多站管理者在這裡就能看出哪個網站該先處理。新帳號會自動帶一個『晨光咖啡烘焙所』示範專案，是我們對一個虛構網站做三次真實掃描的結果，唯讀，讓新用戶不用等掃描就能逛完所有功能。」

**總覽 `/projects/:id`**
「進到一個網站的總覽。最上面三個數字：綜合分數、目前問題數、和上次掃描比新增了幾個。接著是五個維度各自的分數與走勢——同一個網站 SEO 可以 89 分、UX 只有 43 分，問題集中在哪一眼看得出來。下面是問題嚴重程度分布、各維度問題數量、AEO 問答摘要、效能與網站架構摘要、最近幾次掃描。『優先改善建議』是這次最該先做的五件事。如果這次有檢查沒跑完，這裡會明講哪些維度只是部分評估，不會把『沒測到』顯示成滿分。」

**掃描與報告 `/projects/:id/scans`**
「建立掃描在同一頁：範圍選單頁或全網站（最多 50 頁），五個維度可以勾選，被動或主動模式。主動模式有兩道閘：一定要勾資安，而且這個網域要先通過所有權驗證，否則按鈕不會給你送。右邊是費用試算：頁數乘維度乘每維單價，再加符合條件的 AI Agent 附加費；預扣是上限，掃完依實際頁數結算，多扣退回，失敗或取消全額退。下面是歷次掃描的紀錄：範圍、狀態、分數、變化、頁數、問題數、實際扣點，每一筆都能進結果、看問題分析、下載 PDF。」

**掃描進行中（同頁或 `/scans/:id`）**
「掃描是背景任務，關掉瀏覽器照跑。進度條分細階段：爬取、五個維度逐頁分析、AEO 問答、主動探測、深度資安、連結檢查、AI Agent、評分，每一階段各自有進度。下面的執行紀錄是即時 log，爬到第幾頁、每一階段找到幾項問題都看得到。」

**掃描詳情報告 `/scans/:id`**
「掃描完成後的互動報告。最上面是整體分數、嚴重度分布、五個維度分數，接著『優先處理』列出最該先修的項目。中間是問題檢視器，可以依維度、嚴重度篩選。點任何一筆『查看詳情』會看到四樣東西：問題是什麼、原始證據片段、截圖上用框標出實際元素的位置、怎麼修，另外有一段可以直接複製貼給 ChatGPT 或 Claude 的提示詞。資安問題還會標類型：設定建議、曝露面、疑似弱點、已驗證弱點，讀者知道哪些是真的打到、哪些只是觀察。」

**報告上方分頁：網站優勢／架構與信任／網站拓撲／效能／分數說明**
「報告不只講壞的。『網站優勢』列出做得好的地方，每一項附依據，例如 HSTS 的 max-age、DMARC 的政策值。『架構與信任』辨識網站在不在 CDN 或反向代理後面、使用的技術、安全標頭等第、五層信任輪廓、對 24 個 AI 爬蟲的政策。『網站拓撲』是放射狀圖，節點顏色是那一頁最嚴重的問題。『效能』是 Google Lighthouse 與真實使用者資料，只測首頁、不計入 Argus 分數。『分數說明』把每個維度的每一分怎麼扣的攤開，包含只修好這一項分數會回到幾分。」

**產生 AI 解讀**
「這一顆按鈕按了才會花 token。AI 讀完這次的問題與遮罩後的證據，給一段整體診斷、最多三件建議先處理的事，並複核高風險問題是不是可能誤報。它不會改嚴重度、不會改分數，畫面標明是 AI 產生、僅供參考；AI 沒經工具驗證的觀察不會被排在第一優先。」

**問題分析 `/projects/:id/issues`**
「這一頁回答『到底有哪些問題、該先修哪個』。同一條規則在很多頁出現會合併成一個問題，表格列嚴重度、問題與說明、分類、影響頁數、建議重點；可以依維度、嚴重度、變化篩選，匯出 CSV。有三個值得指的設計：第一，『改一處就能一起解決』會把修法在同一處的問題歸成一組，例如五個回應標頭問題其實都在伺服器設定改一次；第二，和上一次掃描比較分『新增、持續、本次未出現』，而『本次未出現』不等於修好了——只有同一項檢查這次完整跑完、受影響頁面也重新檢查過，才標『已修好』，否則標『本次未觀察到』或『本次未檢查』；第三，GEO 這類加分性質的資訊提示被放在下面的『軟性建議』區，不和要處理的問題混在一起。」

**資安分析 `/projects/:id/security`**
「資安的專頁。最上面是資安分數——這是確定性檢查的基準分，AI 深度測試的觀察另外以『AI 深度測試 N 項』獨立呈現，不混進分數，因為 AI 的發現會隨運氣跳動，分數要能跨次比較。接著是安全標頭參考等第，依 Mozilla Observatory 公開規則離線算出 A+ 到 F。『問題類型』把資安問題分成設定建議、曝露面、疑似弱點、已驗證弱點四種並可篩選。『改一處就能一起解決』同上。『API 端點』列出爬取時網站前端自己呼叫的同站 API，加上從前端 JavaScript 靜態找到的端點，每個端點標狀態碼、內容類型、有沒有發現——這就是我們對後端 API 做黑箱檢測的證據，包含錯誤堆疊洩漏、CORS 任意來源、未登入就能讀成批記錄。最下面是本次未出現的資安問題，附覆蓋狀態。如果主動探測被 WAF 擋下，這裡會寫『部分評估』，不會假裝全部查完。」

**SEO 分析 `/projects/:id/seo`（四個分頁）**
「SEO 分析是給網站主逐頁查證、逐項修正的工作清單，分四個分頁。
『概覽』：SEO 分數與等級、掃描頁數、受影響頁數、重大問題、可索引頁數、Google 已收錄、失效連結，下面是優先修復事項與全部問題，每個問題展開會列受影響網址、證據與檢測時間。注意『可索引』是 Argus 依頁面判斷，『Google 已收錄』只由 Search Console 回答，兩者分開顯示，不混為一談。
『頁面與內容』：每一頁一列：HTTP 狀態、可索引、Google 收錄、Title、Description、H1、標題結構、正文、圖片 alt、載入時間。點一頁會開右側抽屜，有搜尋結果預覽、全部檢查與修法、H1 到 H6 大綱、圖片與連結。中文不套英文字數門檻，Title 與 Description 以顯示寬度計算。
『連結』：收集所有連結檢查狀態與每一跳轉址鏈，依站內、子網域、站外分類；302 轉到 200 不算失效，對方拒絕檢查標『無法確認』而不是失效；站內連結過半無法確認時會說明比較可能是 WAF 擋下檢查。和上次掃描比較時，失效連結標新壞掉、持續失效、已確認恢復。
『搜尋關鍵字』：連接 Google Search Console 後顯示真實搜尋詞的曝光、點擊、點閱率、平均排名與對應頁面。目標關鍵字由使用者設定，Argus 檢查它有沒有出現在 Title、H1、Description、小標、網址與正文，並和 Search Console 做落差分析：最佳排名在第幾頁、Google 帶訪客去的頁面和內容最相關的頁面是否一致。『網站自己宣告的關鍵字』讀的是 meta keywords 標籤——對排名無效，但是網站主的意圖，拿來對照實際內容與實際搜尋詞。『有曝光但還不是目標的搜尋詞』是市場告訴你的機會，可以一鍵設為目標。」

**AEO 問答 `/projects/:id/aeo`**
「這一頁回答『訪客會問的問題，網站答得出來嗎』。上面是可回答性分數與逐題統計：可回答幾題、資訊不足幾題、內容衝突幾題、無答案幾題。題目不是 AI 出的，是規則式：13 種固定意圖只有網站正文談到才出題，加上網站自己寫的問句標題。逐題結果列判定、理由與原文證據，可回答的題另標可信度『確認、可能、推測』，以及這段答案能不能被 AI 引用——頁面 noindex 或 nosnippet 會讓答案無法被引用。整個網站沒談到的題不計分，不會因為不賣東西就被扣退貨題的分。判定準確率有人工標註的回歸資料集鎖在測試裡。」

**頁面 `/projects/:id/pages`**
「一次掃描檢查過的每一頁：狀態碼、載入時間、問題數與最高嚴重度、各維度問題數。可以篩『有問題』『錯誤或被阻擋』『載入慢』，搜尋與排序，點進去看截圖。沒有對應頁面的站台層級發現會另外列。這一頁的另一個入口是『優化此頁』。」

**網頁優化 `/scans/:id/rebuild/:rid`**
「優化是 AI 代理對單一頁面產出兩層修改：技術層與視覺層。畫面是原始、發現的問題、Argus 的修改清單、優化後、前後對照，還有改善指標。做法是確定性複刻原頁面後，讓代理只輸出修改清單、不重寫整頁，所以 token 用量小、依實際用量計費。結果可以用唯讀連結分享給設計師或工程師。」

**報告查驗 `/verify`**
「PDF 報告會被轉寄、存檔。每份報告有編號，公開查驗頁輸入編號會回報目標網址、掃描時間、整體分數與 PDF 的 SHA-256 指紋；收件者自己算檔案雜湊就能比對是不是原件。查驗頁不會回傳是誰掃的。」

**網域驗證 `/domains`**
「這是主動掃描的授權閘。被動掃描只讀公開回應，任何網站都可以；主動掃描會送探測與攻擊測試，必須先證明你擁有這個網域：Google Search Console 擁有者是主要方法，另有 DNS TXT、首頁 meta 標籤、驗證檔三種備用。驗證 90 天有效。管理員可以人工核准或否決。」

**購點與訂閱 `/billing`**
「點數制為主、月訂閱為輔。上面是餘額與這個月的贈點，購點方案四種、訂閱方案三種，走綠界金流，訂閱是信用卡定期定額每月扣款。首次完整掃描免費，每月贈點讓使用者定期回來看一次不用付錢。本次展示用測試環境，不會實際扣款。」

**MCP 接入 `/mcp`**
「進階使用者可以在這裡建立 API 憑證，在 Claude Code、Cursor 這類支援 MCP 的工具裡直接呼叫 Argus：建立掃描、查結果、下載報告。憑證只存雜湊、可隨時撤銷；每次呼叫檢查訂閱額度。」

### 管理後台（staff）

**概覽 `/admin/overview`**
「後台首頁。『今日與本月』是脈搏：掃描數、新用戶、購點金額；14 天趨勢圖；下面是總量與成本明細。評審關心的商模數字在這裡看得到。」

**掃描任務 `/admin/scans`**
「所有使用者的掃描任務：帳號、網址、範圍、狀態、進度、警示。點一筆看詳情，可以終止進行中的掃描（合作式取消，worker 在下個檢查點停下並退款），失敗或取消的可以重新排程，重排不重複扣點。」

**使用者 `/admin/users`**
「使用者清單與詳情：錢包餘額、訂閱狀態、掃描紀錄、交易紀錄、登入活動（方式、IP、時間）。調整點數必須填原因，每一筆都進稽核。停用與刪除依對象權限：一般管理員不能動超級管理員。」

**網域驗證 `/admin/domains`**
「所有使用者的網域驗證紀錄與狀態，管理員可以人工核准或否決——這是授權閘的最後一道人工關卡，每次操作都留稽核。」

**訂單與點數交易 `/admin/orders`、`/admin/transactions`**
「訂單是購點與訂閱的綠界交易；每期扣款另有一張表供人工開立發票。點數交易是帳本，每一筆記異動與異動後餘額，不可修改，補正只能新增一筆調整交易——這是計費稽核的基礎。」

**評論治理、網站內容、合作洽談**
「評論是完成過掃描的會員才能發表，管理員可以回覆、隱藏、處理檢舉。網站內容是公開頁的 CMS：功能介紹、團隊、版本紀錄、方案。合作洽談是公開表單送進來的名單。」

**系統健康 `/admin/health`**
「正式環境跑在 Kubernetes，一台 master、三台 worker。這一頁先看掃描鏈路：資料庫、Redis、Celery worker、佇列到掃描，哪一環斷了後面就不流動。接著是每個節點的卡片：角色、Ready 狀態、CPU 與記憶體用量或 requests 佔比、pod 數。再來是 Argus 的工作負載：web、worker、ZAP 各有幾個 pod、就緒幾個、在哪個節點、重啟幾次。最後是檢查明細。」

### 超級管理員（superuser）

**授予管理員 `/admin/users/:id`**
「只有超級管理員能把一般使用者設為管理員或取消；不能動自己、不能動其他超級管理員，這些都在伺服器端擋。最後一位超級管理員無法被刪除。」

**公告 `/admin/announcements`**
「站方公告，常駐或臨時，會員端的通知鈴會顯示。」

**操作日誌 `/admin/audit-log`**
「所有管理行為的稽核軌跡：誰、何時、對誰、做了什麼、前後值。只能查詢、不能刪除。評審問『使用者活動紀錄』時，這一頁加上登入事件、掃描 log、點數帳本，就是四類紀錄的完整答案。」

  畫面已是最新。
