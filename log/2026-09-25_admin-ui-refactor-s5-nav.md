# 後台 UI 重構 S5：側欄導覽分組

**日期**：2026-09-25  
**操作者**：Claude

## 變更內容
- `AdminPages.jsx`：`ADMIN_NAV_ITEMS`（10 項平鋪陣列）改為 `ADMIN_NAV_GROUPS`（四組，每組 3 項），項目以 `superuserOnly` 旗標標記權限而非在渲染時另外拼接陣列。
- 側欄改為分組渲染，每組加上 `role="group"` 與 `aria-labelledby` 指向分組標題。
- 導覽標籤改得更具體：概覽→待辦中心、掃描→掃描任務、網域→網域驗證、交易→點數交易、方案→方案與定價、設定→系統資訊、內容→網站內容、評論→評論治理。
- `AdminSettingsPage` 標題由「系統設定（唯讀）」改為「系統資訊」。
- `styles.css` 新增 `.admin-nav-group` / `.admin-nav-group-label`。

## 原因
規劃 §1-2 問題 J：原本 staff 看到 10 項、superuser 看到 12 項，全部平鋪，超過專案 `argus-ui-design` skill 訂的 5–7 項上限，掃視成本高且看不出項目彼此的關係。

分組依據是「使用者來後台做什麼」而非資料表結構——四組對應四種到訪目的：處理今天的事（營運）、回應客戶（客戶）、維護內容（內容與社群）、調整系統（系統）。

「設定」更名為「系統資訊」：該頁是唯讀的 key-value 檢視，不能設定任何東西，原名稱會讓人以為點進去可以改設定。

`superuserOnly` 項目對 staff 完全不顯示而非 disabled：看得到卻點不了只會製造挫折，且無助於理解自己的權限範圍。

## 影響範圍
- 只影響後台側欄與設定頁標題；路由、權限判定與各頁內容皆未改動。
- 行動版抽屜的 focus trap 查詢的是 `"button, a[href]"`，分組標題是 `<p>` 不影響 tab 序。

## 驗證方式
- `npx vite build` 通過（13.31s）。
- 舊結構殘留檢查：`ADMIN_NAV_ITEMS` 與 `navItems` 皆已歸零。
- 以 Pillow 模擬側欄比對前後：12 項平鋪 vs 四組各 3 項。
- **待人工確認**：staff 帳號登入時「公告」與「操作日誌」應完全不出現，且「內容與社群」與「系統」兩組仍各顯示 2 項（不會出現空的分組標題）；行動版抽屜的 Tab 循環與 Esc 關閉是否正常。
