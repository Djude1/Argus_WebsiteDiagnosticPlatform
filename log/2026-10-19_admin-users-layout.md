# 後台使用者頁審閱：詳情頁區塊順序（2026-10-19）

## 審閱結論
列表（搜尋 → 可排序表格 → 分頁）合理。詳情頁原順序：
基本資料｜錢包 → **帳號狀態（停用／永久刪除）** → 管理權限 → 調整點數 → 訂閱 → 登入記錄 → AI 使用量 → 掃描紀錄 → 交易。
停用與永久刪除這類危險操作是頁面第二個區塊，排在每天都在做的調整點數、訂閱之前；
程式註解自己寫的「客服第一手資料」掃描紀錄卻在倒數第二。

## 變更（`features/admin/AdminUsersPages.tsx`）
順序改為：基本資料｜錢包 → 調整點數 → 訂閱管理 → 掃描紀錄 → 最近交易 → 登入記錄 → AI 使用量 → 管理權限 → 帳號狀態。
日常作業在前、稽核資料居中、權限與停用／刪除放最後；帳號狀態面板加 `admin-panel-danger`（與會員端設定頁的刪除帳號一致）。

## 驗證
`npm run lint`、`npm run typecheck`、`npx vitest run`（既有 20 個使用者頁測試，測的是行為不是順序）。
