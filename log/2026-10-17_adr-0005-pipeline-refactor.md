# ADR-0005：掃描管道重構評估（相位分離與工具去重疊）

**日期**：2026-10-17
**操作者**：Claude
**類型**：純文件（架構評估／實作計劃），未改動任何掃描程式。

## 背景
使用者要求從第一性原理重新評估 17 步掃描管道的順序、階段整合，以及 ZAP／Nuclei／Katana／
Hermes-Agent 是否重疊重複審查。經讀 code 確認現況：資安工具是逐一疊加、各自帶發現＋偵測＋產出，
重疊靠事後去重（ZAP `OVERLAP_RULES`、`cross_layer`、agent `consolidate`）。

## 產出
`docs/adr/0005-scan-pipeline-tool-integration.md`：
- 第一性原理把發現歸成 5 種偵測機制（被動／主動探測／爬行／利用／推理）。
- 列出四個真實重疊（被動做兩遍、爬行做三遍、利用無分工、Katana JS 功能半重疊且有真漏洞）。
- 決策：五相位管道（發現→被動→主動探測→利用→Agent→計分）＋單一攻擊面模型。
- 關鍵決策：JS 端點/秘鑰分析搬進 crawler（補外部 JS 秘鑰漏報、繞 CF）、ZAP 被動與自家被動二選一、
  主動探測合併並放寬請求預算（使用者裁定不限重抓）、利用相位加「分工計畫」、Agent 吃既有結果不盲跑。
- 遷移計畫：6 刀依價值／風險排序，建議先做「crawler JS 抓齊＋秘鑰」（低風險純補洞）。

## 重要事實釐清（寫入 ADR）
- 現有去重都是確定性的，不是 AI 事後審查（更正使用者誤解），但「事後清而非源頭不產生」的債屬實。
- 「可重抓」放寬請求量，但**解決不了 Cloudflare 攔截**（非真瀏覽器會吃 challenge）；CF 盲區只能靠
  crawler 真瀏覽器或瀏覽器 context 重抓。Katana JS 功能在 CF 後本就歸零，降級不損覆蓋。

## 驗證
純文件，無程式改動；無測試影響。ADR 內「現況」對照 2026-10-17 的 `backend/apps/scans/` 實際程式。
