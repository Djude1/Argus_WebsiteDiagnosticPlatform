# 審查第二份報告（imd.ntub.edu.tw）後修正：卡號誤遮網址、比較區塊與導讀矛盾、LCP 異常、拓撲標籤、站外連結未檢查

**日期**：2026-10-17
**操作者**：Claude

## 背景
使用者提供另一份正式掃描報告（ARGUS-20261017-2850，imd.ntub.edu.tw，78 分，50 頁）要求審查。這份掃描跑的是上一輪修正部署前的版本（評分版本「計分 v3／規則 2026.10.16」），所以「安全標頭等第 HTTP 轉址到 HTTPS 被誤扣 20 分」又出現一次，已在 `f815fb5` 修正，重掃後會消失。以下是這份報告新發現的問題。

## 變更內容

1. **卡號遮罩把網址裡的頁面編號遮掉（`security/redaction.redact_pii_in_text`）**
   - 現象：4.5「站內連結失效」的檢測依據寫成 `https://imd.ntub.edu.tw/p/4041*****7736.php`，第 1 章的表格是原本的 `/p/404-1043-117736.php`，讀者無法對照、也點不開。
   - 根因：偵測卡號時有 Luhn＋卡組織＋分組／關鍵字的嚴格判斷，遮罩卻只用原始 regex，任何 13–19 位數字（含分隔）都被遮。
   - 修正：遮罩前先要求通過 Luhn 且開頭與位數符合卡組織。真卡號一定通過 Luhn，不會漏遮；比偵測寬鬆（不要求分組或關鍵字），寧可多遮。

2. **導讀說「分數不宜直接比較」，比較區塊卻用綠色寫 +7 分（`reports._report_summary`、`report_render._trend_block`）**
   - 修正：`summary.previous.comparable` 帶出可否比較；不可比較時變化改灰字並註明「評分規則不同，僅供參考」，「新出現」改寫成「本次有、前次沒有（可能來自規則更新）」。

3. **實驗室 LCP 240.8 秒（同一網址 CrUX 真實使用者 1.7 秒）沒有任何說明（`report_site_metrics._performance`）**
   - 修正：實驗室 LCP 超過 60 秒時加註：多半是輪播或動畫讓「最大的畫面元素」持續更換，單次量測記到最後一次變化，不代表訪客要等這麼久，有真實使用者資料時以 CrUX 為準。

4. **網站拓撲圖 50 個標籤疊成一團、還有重複的標籤（`report_render/charts.topology_map`、`report_site_metrics._path`）**
   - 根因：第一層頁面一律標路徑；標籤只取路徑、丟掉查詢字串，`?Lang=en` 與 `?Lang=zh-tw` 兩個語系版本顯示成同一個標籤。
   - 修正：第一層超過 16 頁（`TOPOLOGY_MAX_LABELS`）時只標入口頁，說明文字改成「第一層有 N 頁，標籤太多會重疊…各頁網址見網頁版」；標籤與「出現在」欄保留查詢字串。

5. **子網域與站外連結一個都沒檢查（`seo/collect._reserve_outbound`）**
   - 現象：站內 311 個連結把 150 個的檢查額度用完，子網域 14、站外 21 全部「未檢查」。
   - 修正：超過上限時，子網域＋站外保留 25% 額度（不足就全給站內）。

`RENDERER_VERSION` 32 → 33（比較區塊、效能加註、拓撲標籤）。

## 審查結果但不需修改的項目
- 4.6／4.7 ARIA 屬性與角色（`aria-expanded` 用在一般文字輸入框、owl carousel 的 `role="tab"` 沒有 `tablist` 父層）：axe-core 判斷正確，是網站本身的問題。
- 4.4 核心內容依賴 JavaScript（原始 HTML 2349 字、渲染後 4938 字）：判斷依據清楚，合理。
- API 端點清單只有一筆 `POST /app/index.php`（回 HTML）：是前端實際呼叫到的同網站請求，照實列出。
- AEO「聯絡 Email」判資訊不足而資安列出 Email：卡片已說明兩者判定情境不同。
- 實際搜尋詞：這個專案還沒連接 Search Console，屬設定問題。

## 驗證方式
- 後端：`ruff check backend` 通過；`manage.py check` 無問題；`makemigrations --check` 無變更；後端全套 1970 項通過（skipped 12）；根目錄 `tests/` 36 項通過。
- 新增測試：網址頁面編號不被遮、真卡號仍遮；可否比較旗標；實驗室 LCP 異常加註（一般慢不加）；拓撲標籤保留查詢字串；站外連結保留額度（站外少時剩餘全給站內）。
- 調整兩個既有測試的前提：PII 截斷測試的「卡號」改成通過 Luhn 的號碼（真卡號一定通過）；報告比較測試把兩次掃描設成相同評分版本（版本不明的兩次掃描本來就不該說「新出現」）。
- 實際畫出 30 個第一層節點的拓撲圖確認：只標入口頁、不重疊。
- 需正式環境重掃確認：4.5 檢測依據的網址完整、安全標頭等第不再扣 HTTPS 轉址分、站外連結有檢查結果、拓撲圖可讀。
