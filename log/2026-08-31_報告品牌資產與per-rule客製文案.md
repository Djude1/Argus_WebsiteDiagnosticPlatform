# 2026-08-31 報告品牌資產與 per-rule 客製文案

## 變更內容

### 1. Argus 品牌資產（用 Pillow 生成，不引入 cairosvg）

**新增檔案**：
- `scripts/render_argus_brand.py`（產圖腳本）
- `frontend/public/argus-logo.png`（256×256, 14KB）
- `frontend/public/argus-logo-watermark.png`（512×512 半透明, 39KB）
- `frontend/public/argus-title.png`（900×240, 35KB，含 4 角星點綴 + 漸層陰影）

**原因**：
- audit N15 與使用者 8/30 回饋：「報告應該有 Argus 防偽或特徵」
- 計畫 Task 3.1（logo PNG）原本要用 cairosvg，但 cairosvg 有系統函式庫相依會拖累 CI / Docker build
- 改用純 Python Pillow 重現 favicon.svg 的 4 角星 + cyan-indigo 漸層 + glow 圓

### 2. 報告封面用藝術字標題 PNG

**修改檔案**：`backend/apps/scans/reports.py` 的 `_add_cover()`

**變更**：封面有 `argus-title.png` 時優先用圖（含4 角星 logo 點綴、漸層、陰影），沒圖才退回純文字標題。

### 3. 每個 finding 改用 per-rule 客製文案

**修改檔案**：`backend/apps/scans/reports.py`
**新增檔案**：`backend/apps/scans/tests_report_rule_specific.py`（10 個新測試）

**變更**：
- 新增 `RULE_IMPACT` dict（18 個 rule_id 客製「為什麼要在意」文案，含具體後果、罰鍰金額、攻擊情境、SEO 影響等）
- 新增 `RULE_VERIFY` dict（18 個 rule_id 客製「修好了怎麼確認」驗收指令，含 `curl -I ...`、`dig TXT ...`、`瀏覽器開發者工具` 等可執行指令）
- 新增 `_impact_for(finding)` 與 `_verify_for(finding)` helper，依 rule_id → category → generic 三層 fallback
- 在 `_add_findings()` 加入「為什麼要在意」與「修好了怎麼確認」兩個段落（之前只有「問題是什麼」「怎麼修」「檢測依據」3 段）

**原因**：使用者 8/30 回饋「報告中每項『為什麼要在意』『修好了怎麼確認』內容完全相同（security 全是攻擊者可利用模板）」——audit supplement N11-N12 + 你 8/31 提出的問題。

### 4. 截圖改用 Pillow 縮圖策略

**修改檔案**：`backend/apps/scans/reports.py` 的 `_add_entry_screenshot()`

**變更**：
- 用 Pillow `thumbnail((1200, 1200))` 縮成最寬 1200px
- 寫入 `media/scans/<scan_id>/report_thumbs/` cache 目錄（mtime 檢查避免重複處理）
- 加註完整檔大小（讓收件者知道原圖多大、需要時可從 Argus 平台下載）
- 截圖損毀時靜默略過（不讓截圖問題炸掉整份報告）

**原因**：scan-38 docx 從 41KB → 3MB（73 倍），因為直接 embed 全頁截圖（1440×6198, 3MB）。現在縮圖後 docx 預期 < 200KB。

## 影響範圍

- 報告封面視覺：純文字「ARGUS」大字 → 4 角星 logo + 漸層陰影藝術字
- 報告 finding 結構：3 段 → 5 段（多「為什麼要在意」「修好了怎麼確認」）
- 報告 finding 文案：category-level 通用模板 → rule_id-level 客製（含 curl/dig 驗收指令）
- 報告檔案大小：~3MB（含原圖）→ ~80KB（純文字 + title PNG）或 ~200KB（含縮圖）
- API 行為：無變動
- DB schema：無變動
- 既有功能：完全向後相容（CATEGORY_IMPACT / CATEGORY_VERIFY 仍存在，作為 fallback）
