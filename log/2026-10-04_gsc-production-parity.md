# GSC、登入事件修復與部署一致性驗收

**日期**：2026-10-04

## 變更內容與原因

修復 GSC 網域控制權驗證的回呼路徑、擁有者判定、URL 字首的授權範圍與 state 單次使用保護；整合網站專案的長期報表流程。未完成 Argus 掃描的網站也能先連接 GSC，並正確比對 Unicode／Punycode 網域。合併兩條 migration 分支，同步 API 型別、設定說明與競賽內容。

完整檢查另重現登入事件同時間戳記的排序問題，以 id 降冪穩定排序並新增 model options migration；固定時間的 API 回歸與既有案例共四項通過。報告快取測試在模擬檔案失蹤前關閉串流回應，避免 Windows 檔案鎖；七項快取案例通過，產品下載行為不變。

## 影響範圍

網域控制權驗證與網站專案報表各自使用回呼，兩者同時啟用時固定回呼覆寫應留空。Google Client Secret 及既有 token 不隨程式發佈；各環境須分別完成 OAuth 設定與 Google 授權。保留 Google HTML 驗證檔。

## 已執行驗證

相關後端 140 項、前端 190 項、部署契約 43 項通過；Ruff、Django check、migration 漂移檢查、TypeScript、前端 build 通過。ESLint 0 errors，另有一項既有 hooks warning。既有本機一般帳號的 SEO、GSC 狀態與 connect API 回 200；未連接的資料端點回 404。

初次完整測試的報告錯誤由本機缺少 CJK 字型設定造成；已以既有字型補齊環境，圖表由主代理及獨立 QA 實際觀看，中文字型範圍無缺字或裁切。沒有將單機字型路徑納入發佈。最終完整 1414 項檢查完成，1412 通過、2 跳過（Linux 子程序群組與隔離 Redis），無失敗或錯誤；真實 LibreOffice 轉檔案例通過，尚未對完整 PDF 做視覺驗收。

## 發佈驗收條件

新版回呼由使用者儲存後，本機真實 Google 授權成功。改用有目標資源權限的帳號授權後，資源選擇、7／28／90 天搜尋成效與首頁／子頁網址檢查均回 200，包含真實搜尋資料及同期比較欄位；子頁未建立索引是 Google 資料結果，不是 API 失敗。私有搜尋資料與授權憑證不納入紀錄。

正式站仍須核對發佈版本、CI、GitOps 回寫、公網資產及正常登入後的操作；相同資源、期間與篩選條件的 API／畫面應一致。健康檢查或 mock 通過不代表真實 Google 資料測試完成。此紀錄尚不宣稱修復已發佈或正式 GSC 端到端已通過。
