# 重設計登入後購點結帳頁

**日期**：2026-08-22
**操作者**：Codex

## 變更內容

- 重構 `BillingPage` 的結帳標頭、Stage 狀態、三步進度、資料表單、訂單摘要與確認頁文案。
- 將聯絡資料、個人／公司購買、載具偏好及公司資料改為有清楚層級、永久 label 與欄位錯誤關聯的表單。
- 新增 `/billing` 專屬桌面、平板與手機樣式；桌面採表單＋sticky 摘要雙欄，900px 以下改為單欄。
- 移除已不再使用的舊發票 pill、測試 banner 與 wizard 表單樣式，避免互相覆寫。
- 依本機驗收回饋提高訂單摘要標題、欄名與保障說明的字級、對比及行距，改善深色背景閱讀性。
- 新增 `memory/billing-checkout-redesign.md`，記錄系統能力邊界、設計決策與 QA 限制。

## 原因

原頁面將測試環境、進度、方案、聯絡資料、發票類型、載具與條款攤在同一層，寬螢幕留白過大且文案誤稱會自動歸戶／開立正式發票。重設計目標是讓使用者快速理解購買順序、當前方案、測試金額與必要資料，同時忠實呈現 repo 目前只有綠界 Stage 與購買收據的能力。

## 影響範圍

- 影響登入後 `/billing` 的三步購點流程與視覺樣式。
- 未修改公開 `/purchase`、billing API、資料模型、簽章驗證、callback 或點數入帳邏輯。
- 本機未送出外部綠界付款表單，也未建立測試訂單；最近 30 分鐘新增訂單數查核為 0。
- UI 預覽觸發購買 API 時，既有 billing migration／source 漂移會在 `payment_mode` 非空限制處回滾；未納入本次前端修正範圍。
