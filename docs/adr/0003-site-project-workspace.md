# 會員區改為「以網站專案為核心」的工作區

會員區原本以「掃描任務」為中心：Dashboard 是全帳號統計、`/scans` 列出每個網址最新一次掃描、`/history` 依 origin 分組列歷次分數。同一個網站的總覽、問題與報告散在三個頁面，而且只能靠網址字串把它們湊起來。使用者實際的工作單位是「我的某個網站」——參考 Sitechecker：頂部工具列切換網站、側邊欄使用目前網站的各項功能。

## 決策

### 1. 資料關係

```
User 1 ── * SiteProject（網站專案）1 ── * ScanJob 1 ── * Finding / Page
                 │
                 └─（依 hostname 查詢）VerifiedDomain（網域所有權，不直接關聯）
```

- **一個網站專案＝一個使用者的一個 origin**（scheme＋host＋port），`UniqueConstraint(user, origin)`。專案名稱預設為 hostname，可改；起始網址（新掃描的預設網址）必須在同一個 origin 內。
- **每筆 `ScanJob` 都屬於一個專案**（`ScanJob.project`）。建立掃描時可指定專案；沒指定（MCP、舊用戶端、後台重排、測試）時由 `ScanJob.save()` 依 origin 自動歸入（沒有就建立）。migration 以既有掃描的 (user, origin) 回填專案。
  - 指定專案時網址的 origin 必須與專案相同，否則拒絕（換網站＝換專案）。
  - FK 用 `SET_NULL`：專案不提供硬刪除，刪除使用者時才可能一起消失，掃描與點數交易紀錄不能因此被連帶刪掉。
- **移除專案＝封存**（`archived_at`）：從清單與切換器消失，掃描、報告、點數紀錄全數保留；同一網站再新增專案或再建立掃描時自動恢復原專案（歷史接得上）。
- **網域驗證不併入專案**：`VerifiedDomain` 涵蓋子網域（驗證 `example.com` 後 `www.example.com` 也可主動掃描），與專案的 origin 粒度不同；專案只顯示「此網站目前是否可做主動測試」並連到網域驗證頁。
- **專案層級預設掃描設定**（`default_scope`、`default_categories`）：「掃描」分頁的表單以此為初始值，每次掃描仍可調整；表單草稿按專案分開存，A 網站沒送出的設定不會帶到 B 網站。
- **問題只收本次有勾的維度**：掃描流程的部分站台層級檢查（DNS 郵件紀錄等）不論勾選都會寫入 finding，但沒勾的維度不計分、報告顯示未評估，問題分析與總覽的優先建議必須一致。
- **問題的追蹤單位＝一次掃描中「同一條規則」**（`rule_id`，無則「分類＋標題」），與報告的合併規則一致。跨掃描比較時：本次有、上次沒有＝新增；兩次都有＝持續；上次有、本次沒有＝「本次未出現」。後者只在本次仍檢查了該分類時才列出（沒勾的維度不能算已修好），並明講「未出現不等於已修好」（可能沒爬到該頁）。另計「連續 N 次」：往回數同專案連續幾次完成的掃描都出現該問題（遇到沒出現或那次沒勾該維度就停），讓拖很久沒修的問題浮上來。

### 3. 使用流程

1. **第一次使用**：登入 → `/dashboard` → 沒有專案 → 新增專案（輸入網址）→ 進入該專案的「掃描」分頁 → 建立第一次掃描 → 掃描詳情（側邊欄仍是該專案）。
2. **持續管理**：登入 → 自動回到上次的專案總覽 → 看分數變化與新增問題 → 問題分析篩選處理 → 修好後回「掃描」重新掃描 → 總覽與問題分析顯示新增／持續／未出現。
3. **多個網站**：頂部切換器切換專案，停留在同一個分頁（例如從 A 的問題分析切到 B 的問題分析）；掃描詳情切換時回到新專案的總覽。
4. **舊資料**：migration 依 (使用者, origin) 自動建立專案並歸入既有掃描，使用者不需任何操作。

### 4. API

- `GET /api/projects/?archived=true`（列已封存）、`GET/POST /api/projects/`、`GET/PATCH/DELETE /api/projects/<id>/`（DELETE＝封存）、`POST /api/projects/<id>/restore/`
- `GET /api/projects/<id>/overview/`（含 `latest.stats`／`category_counts`／`aeo` 與 `recent_scans`）、`GET /api/projects/<id>/issues/?scan=<id>`（每個問題含說明、修法與最多 50 個受影響網址）、`GET /api/projects/<id>/pages/?scan=<id>`
- `GET /api/scans/?project=<id>`：該專案全部掃描（不做「每個 origin 只留最新」的收合）
- `POST /api/scans/` 可帶 `project`；`ScanJobSerializer` 回傳 `project`

## 考慮過的選項

- **專案＝registrable domain（含子網域）**：`blog.example.com` 與 `shop.example.com` 通常是不同網站、不同掃描設定，分數混在一起沒意義；且與既有「同 origin 比較前次掃描」的報告邏輯不一致。否決。
- **允許同一 origin 多個專案**（例如不同掃描設定）：切換器會出現兩個一樣的網站，自動歸入也無法決定歸哪個。v1 否決。
- **排程掃描**：有價值但這次不做（需要 Celery beat 與計費確認流程）；預設掃描設定已就位，之後排程可直接沿用。
- **掃描詳情改成 `/projects/:id/scans/:scanId`**：MCP、報告、通知與使用者手上的連結都是 `/scans/:scanId`，改網址會讓它們全部失效；改由外層依掃描所屬專案顯示側邊欄。否決。
- **硬刪除專案**：會連帶刪掉掃描與點數交易關聯，違反計費稽核規則。改為封存。

## 第二版修訂（2026-10-02，依第一版實測經驗）

第一版上線前回退，這次以同樣的資料關係重做並補上實測發現的不足：專案預設掃描設定與按專案分開的表單草稿、問題「連續 N 次」、已封存專案可在清單直接恢復、所有專案頁的跨網站總覽、切換器顯示分數／搜尋／方向鍵、側邊欄圖示與新掃描捷徑、總覽的掃描進度條，以及問題分析只收本次有勾的維度。第一版實測修正的三個問題保留：`/projects` 被 `startsWith("/project")` 誤判為公開頁、網域驗證頁呼叫錯誤路徑 `/api/scans/domains/`、側邊欄 sticky 滑進導覽列底下。

## 第三版補強（2026-10-02）

使用者回饋工作區「太簡單、少了很多東西」：總覽改成完整儀表板（見上表），新增「頁面」分頁，問題分析加上說明與修法展開、依維度分組與 CSV 匯出。各維度走勢用 small multiples（每個維度一條、列上標名稱）而非一張五色折線——品牌的 SEO／AEO 類別色色差不足，不能只靠顏色辨識。同時整站掃描改為以 sitemap 補種子、預設深度 3→6，連結稀疏的網站也能達到 50 頁上限。

## 第四版：去除 SaaS 卡片感、網站圖示、掃描詳情重排（2026-10-02）

- **外觀**：使用者指出「圓角白卡片＋淡灰底＋彩色左邊條＋彩色徽章＋線條圖示＋右上角主按鈕」組合起來是典型 AI SaaS 儀表板味。一度改為報告式（白底細線、底線選中、色點徽章），2026-10-03 使用者回饋太素，**改回卡片、淡灰底與彩色徽章**，只保留：選中不用彩色左邊條（用淺藍底）、不用 emoji。2026-10-03 使用者提供參考設計後，再加回側邊欄圖示、總覽右上角的「查看最新報告／開始新的掃描」，並把各分頁頁首統一成 `ProjectHeader`（網站圖示、驗證勾勾、首頁 meta description、最後掃描狀態）。
- **網站圖示**：`SiteProject.favicon`（data URL）在**新增專案時立刻抓**（首頁宣告的圖示或 `/favicon.ico`，整體 8 秒上限；2026-10-03 使用者要求加入網站當下就要有），之後掃描流程的 `favicon` 階段用爬到的首頁更新（每 7 天最多一次）；縮成 64px PNG、SSRF 檢查每一跳、大小上限、可辨識的 User-Agent；切換器、側邊欄、總覽與所有專案顯示。前端不直接連目標網站載圖示——那會把使用者的 IP 送給受測網站、也受 CSP 限制。
- **所有專案**：卡片改為網站登記表（分數與變化、歷次走勢、各維度分數、目前問題依嚴重度、上次掃描），可排序與搜尋；`summary` 新增 `score_history`、`issue_counts`。
- **示範專案與新增專案頁（2026-10-03）**：新帳號原本進來是空白頁面，看不出 Argus 能做什麼。現在建立帳號時自動建立唯讀的示範專案，資料來自虛構網站的三次真實掃描，而不是手寫假資料，所以每個分頁與報告的內容都和真實掃描同一種形狀。示範專案不能建立掃描，也不能修改；後台統計與評論資格都不計入。新增專案頁原本只有網址與名稱，改成三段：網站資料與說明、預設掃描設定（範圍、維度、模式）、建立之後，並加上即時預覽與點數估算。
- **導覽列**：移除「首頁」（指向公開產品介紹，與登入後的工作無關，入口移到帳號選單），品牌改回所有專案；中等寬度（分屏）時切換器與品牌、帳號同一列且有寬度上限，不再獨佔一大塊。2026-10-03 依參考設計改成工具列：不再有文字連結，所有專案／網域驗證／MCP 移到頭像選單，加上 ⌘K 搜尋（專案、分頁、最新掃描的問題）與通知鈴（站方公告，取代總覽的公告 toast）。
- **掃描詳情**：頂部改為「← 返回所有掃描」＋「報告／網站結構圖／修正產出」分頁；報告頁依序是標題與分數 → 摘要（嚴重度、各維度、優先處理）→ 檢視器（左：頁面／維度／嚴重度篩選與問題清單；右：選中問題的說明與證據、固定高度可捲動的截圖、該頁的複刻工具）→ 執行紀錄。優先處理放在截圖之前，任何寬度都不會被擠到截圖下方；頁面選擇由一排標籤改成下拉選單（50 頁時標籤會塞滿畫面）。
- **AEO 問答** 移到專案側邊欄的獨立分頁；**修正產出**保留（正式環境啟用、會產出可貼上的 JSON-LD／llms.txt 等並計點），從報告最下方移到掃描的「修正產出」分頁。
